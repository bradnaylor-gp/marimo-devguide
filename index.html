Building Interactive Apps with Marimo

Developer's Guide to Starting with Reactive Python Workbooks

What is Marimo?

Marimo is a reactive Python notebook built for data scientists, engineers, and developers. It enables the creation of responsive, dynamic applications with clean and maintainable code. Unlike traditional notebooks, Marimo uses a cell dependency model that automatically updates dependent cells when inputs change.

Reactive Programming

Cells automatically update when their dependencies change, creating a reactive data flow.

Interactive UI Elements

Built-in components for building user interfaces with sliders, buttons, dropdowns, and more.

Dependency Tracking

Explicit declaration of dependencies makes code easier to understand and maintain.

Shareable Apps

Export workbooks as standalone applications that can be shared with anyone.

2. Cell Dependencies

Each cell is a function decorated with @app.cell. Dependencies are explicitly declared through function parameters, creating a reactive data flow. 

@app.cell
    def setup():
    import marimo as mo
    import pandas as pd
    import altair as alt
    return alt, mo, pd

    @app.cell
    def create_chart(alt, pd, data):
    chart = alt.Chart(data).mark_bar()
    return chart

Best Practices

Import Management

  • Import libraries once in a setup cell
  • Return imported modules to be used by other cells
  • Keep dependencies explicit
@app.cell
    def setup():

Variable Scoping

  • Use function parameters to declare dependencies
  • Return values that other cells need
  • Avoid global variables
  • Create focused, single-purpose cells

Layout Components

Horizontal Layout

@app.cell
    def horizontal_layout(mo, element1, element2):
    layout = mo.hstack([
        element1, 
        element2
    ], justify="space-between")
    return layout

Vertical Layout

@app.cell
    def vertical_layout(mo, title, chart, table):
    layout = mo.vstack([
        mo.md("# " + title),
        chart,
        table
    ])
    return layout

Markdown

@app.cell
    def create_markdown(mo, value):
    markdown = mo.md(f"""
    ### Statistics
    **Value:** {value}
    """)
    return markdown

Data Processing & Visualization

Reactive Data Processing

@app.cell
    def process_data(df, filter_value):
    if filter_value.value != 'All':
        filtered_df = df[df['category'] == filter_value.value]
    else:
        filtered_df = df.copy()
    return filtered_df

Visualization Integration

@app.cell
    def create_chart(alt, data):
    chart = alt.Chart(data).mark_bar().encode(
        x='category:N',
        y='value:Q',
        color=alt.Color('category:N', scale=alt.Scale(scheme='category10'))
    ).properties(
        width=400,
        height=200,
        title='Chart Title'
    )
    return chart

Common Patterns

1. Reactive Data Flow

  1. Load and prepare initial data
  2. Create UI elements for user interaction
  3. Process data reactively based on UI inputs
  4. Generate visualizations that update automatically
  5. Compose the final layout

2. Filter Pattern

@app.cell
    def create_filters(df, mo):
    filters = mo.ui.dropdown(
        options=['All'] + df['category'].unique().tolist(),
        value='All',
        label="Filter by Category"
    )
    return filters

    @app.cell
    def apply_filters(df, filters):
    filtered_df = df.copy()
    if filters.value != 'All':
        filtered_df = filtered_df[filtered_df['category'] == filters.value]
    return filtered_df

3. Dashboard Layout

@app.cell
    def display_dashboard(mo, filters, stats, charts):
    return mo.vstack([
        mo.md("# Dashboard Title"),
        mo.hstack([filters, stats], justify="space-between"),
        mo.md("## Visualization"),
        charts
    ])

Development Best Practices

  • Keep cells focused on a single task or purpose
  • Explicitly declare all dependencies through function parameters
  • Return all values needed by other cells
  • Test reactivity by changing inputs and verifying updates
  • Use meaningful function and variable names
  • Handle edge cases like empty data frames or missing values
  • Document complex data transformations

Debugging Tips

  1. Check that cell dependencies are correctly declared in function parameters
  2. Verify that all necessary values are returned from each cell
  3. Use print statements to track data flow and transformations
  4. Check the console for JavaScript errors when working with interactive elements
  5. Test each component individually before combining into a complete app

Conclusion

Marimo provides a powerful framework for creating reactive Python applications that transform data science workflows. Its focus on clean code, explicit dependencies, and interactive components makes it an excellent choice for building maintainable data apps and dashboards.

By following these patterns and best practices, you can create robust, interactive dashboards that effectively communicate insights from your data while maintaining code quality.
